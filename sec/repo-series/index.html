SEC Data Engineering Series

Four repos, one dataset: every tagged XBRL fact from SEC EDGAR's companyfacts API, examined from a different angle.

Data SEC EDGAR companyfacts (AAPL, MSFT, TSLA) Stack Python · SQLite · JavaScript — stdlib-first, no heavy deps Theme same number, four questions: is it right? what does it say? is it unusual? can you reproduce it?

How the series fits together

EDGAR companyfacts→ 1 · quality & lineage→ 2 · SQL analytics→ 3 · statistics & viz→ 4 · reproducible process

Each repo stands alone — different tools, different deliverables — but they share the same raw data and the same canonical metric mapping, so findings cross-check. The quality repo's reconciliation engine and the SQL repo's tie-out check independently flag the same Microsoft FY2016 gap; the dashboard's outlier case files explain it.

1sec-data-quality

Where did this number come from, and is it fit for use?

Data-quality checks, reconciliation reports, issue logs, and lineage over EDGAR companyfacts. Every emitted number carries its filing accession, form, and filed date; every number gets a FIT / REVIEW / NOT-FIT verdict.

  • Six DQ rules (missing lineage, duplicates, period sanity, impossible signs, unit mixing, magnitude jumps) + three reconciliation rules
  • Cross-filing reconciliation: the same period compared across every filing that reports it — MATCH / RESTATED / MISMATCH
  • Quarters-vs-annual tie-out and implied-Q4 derivation (the fourth quarter is almost never tagged — analysts derive it)
  • Deliverables: issue_log.csv, lineage.csv, reconciliation.csv, fitness_summary.csv, summary.md
Real catch: Apple's 2009 retrospective restatement and the 7:1 split surfacing as cross-filing EPS mismatches — automatically classified, not hand-found.

2sec-financial-analytics

Query, clean, join, aggregate, validate — in SQL.

The same EDGAR data loaded into SQLite: staging → cleaned fact table → analysis views → validation views that return violations. Python only orchestrates; the logic lives in numbered SQL files.

  • Cleaning in SQL: in-filing dedupe, latest-filed supersession, tag→metric dimension map (three revenue tags collapse to one concept)
  • Aggregates: annual financials, YoY growth via LAG, quarterly flows, operating/net margins, implied Q4, latest-year snapshot
  • Six data tests as violation-returning views; the runner exits non-zero so it's a CI gate
  • Every view exports to spreadsheet-ready CSV
Independently flags MSFT FY2016 — quarters under-report annual net income by $3.7B — the same gap repo 1 catches.

3sec-stats-dashboard

Descriptive statistics, trend analysis, outlier investigation, modeling, chart selection.

An interactive page — live on GitHub Pages — where a Python build layer computes the statistics and the JS layer only renders. Every panel states why its chart was chosen and what it rejected.

  • Descriptives across three windows (annual, quarterly, YoY) with CV/skew interpretation
  • OLS vs log-linear fits side by side, R², CAGR, residual diagnostics — the model is validated by where it's wrong
  • IQR-fence and z>2 outlier flags with click-through case files: every filing that reported the number, plus a restated badge
  • Revenue→income regression, hand-drawn SVG box plots, and a chart-selection decision table

4reproducible-analysis

The habits that make analysis reproducible — the practices are the deliverable.

A deliberately small pipeline where the infrastructure is the point: documented transformations, hashed provenance, gated checks, and review scaffolding.

  • manifest.toml documents every transformation; the PR template requires updating it in the same commit
  • make verify recomputes all outputs from recorded inputs and compares sha256 — byte-identical or it fails
  • Investigated violations are baselined with written reasons; new violations still fail the build
  • Committed outputs → data changes are reviewable as diffs; CI runs tests + pipeline + verify on every PR; PR template, CODEOWNERS, review protocol
The workflow proved itself on PR #1: adding TSLA surfaced a tag-variant double-count bug in the tie-out check — caught, investigated, fixed, documented.
