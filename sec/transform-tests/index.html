The Weekly Late Filers report, rebuilt as five small SQL steps. Each step has unit tests on hand-made fixture rows and data tests on the real EDGAR data. The same tests run here in your browser and in a GitHub Action on every push, and a proposed change gets reviewed with its code diff, test changes and output diff side by side.

How to use
  1. Start with What each transformation does: each query script, the manual reporting task it replaces, and one real notice traced through all five steps. New columns are green and changed values are orange.
  2. Click Run all tests any time to rebuild every step on the real data and check it.
  3. Click a step in the pipeline to see its input and output side by side, its SQL, its unit tests (fixture in, expected out) and its data tests.
  4. Click Introduce a bug, or edit the SQL yourself, then Run tests to watch the tests catch it. Reset SQL puts it back.
  5. In Review a change, run the checks on the proposed change, read the diffs, and approve it or request changes.

1Pipeline

Raw EDGAR tables flow through five SQL steps to the weekly report. Each step reads only the step before it, so each one can be tested alone by giving it fixture rows in place of its input.

5Repeatable workflow

The tests replace the manual check of "does this week's report look right?". They live in the repo next to the SQL and run the same way every time.

A failing test fails the GitHub Action, which turns the badge at the top red. The Action is defined in test-transformations.yml.

Adding a test

Add an entry to the step's unit list in tests.json: a name, why it matters, the input rows and the rows you expect back. Only the columns you list in expect are compared, so a test pins down one behavior.

{ "name": "NT 10-Q gets 5 calendar days",
  "why": "Rule 12b-25(b) gives quarterly reports a 5-day extension.",
  "given":  { "stg_nt_filings": [ { "adsh": "A-1", "form": "NT 10-Q", "filed": "2026-03-04", ... } ] },
  "expect": [ { "adsh": "A-1", "extension_days": 5, "deadline": "2026-03-09" } ] }

Data tests are a SQL query that returns the rows breaking a rule. No rows means pass.
